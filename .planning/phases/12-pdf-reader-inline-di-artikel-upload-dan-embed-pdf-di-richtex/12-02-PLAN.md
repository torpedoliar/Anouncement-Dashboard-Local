<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Editor (Trusted client) -> announced content string in browser | Editor-authored markup is held client-side then sanitized server-side at save (12-01). Client display must not execute anything the server will later reject |
| Editor -> /api/media POST | File + claimed MIME from the editor's own tool; server (12-01) double-validates — this plan only adds the client-side pre-check for UX |
| External URL typed by editor -> data-src attribute | An arbitrary string the editor pastes becomes part of stored markup; it must be scheme-validated client-side AND re-sanitized server-side (12-01 URI regex) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-02-URLSCHEME | Tampering | external-URL dialog -> data-src | high | mitigate | Client dialog rejects non-http(s) and non-.pdf URLs before insert; final authoritative gate is the 12-01 sanitizer URI regex which strips javascript:/data: — defense in depth |
| T-12-02-RENDER | Tampering | renderHTML of Pdf node | high | mitigate | Pdf node emits ONLY the 3 whitelisted attrs; never forward user strings into an href/src of an executable element; editor placeholder uses CSS content, no inner HTML from attrs |
| T-12-02-OPTIMISTIC | Spoofing | optimistic upload block | low | accept | Editor-only visual; transient error attr is stripped by the server sanitizer at save; a failed upload leaves no executable markup |
| T-12-02-POPUP | Spoofing | editor toolbar | low | accept | Editor never opens any new window/tab or auto-downloads; dropdown + modal are in-app only |
| T-12-02-SC | Tampering | npm installs | low | accept | No new dependency (FilePdf icon already in installed @phosphor-icons/react v2.1.10 — verified) |
</threat_model>
