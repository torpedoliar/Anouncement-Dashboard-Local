# Adaptive Login Profile: discovery, approval, and health revalidation

Fase ini memisahkan hasil discovery login menjadi `PortalLoginProfile` reusable, meminta SuperAdmin menyetujui fingerprint, lalu mengikat snapshot itu ke `PortalApp`. Discovery dan revalidasi menyimpan metadata struktural, sementara UI admin menampilkan kandidat dan drift. Binding create/update sudah menolak fingerprint yang tidak cocok, tetapi kontrol tersebut tidak diteruskan ke titik ketika kredensial didekripsi dan dikirim. **Watch for: P0 (confirmed)** raw redirect query/cookie metadata dapat masuk ke evidence, profile stale tidak menghentikan credential forwarding, dan fingerprint tidak mencakup beberapa perubahan perilaku login penting.

**Verdict**: NEEDS_CHANGES

## High-level view

Discovery menormalisasi kolom URL utama menjadi origin/path, tetapi **confirmed** `warnings` dan `discoverySignals` yang dipersistenkan melewati normalisasi: warning redirect membawa `finalUrl` mentah dan signal dapat memuat nama cookie antiforgery.

Approval diperiksa ketika aplikasi disimpan, tetapi **confirmed** jalur peluncuran SSO tidak memeriksa state atau fingerprint profile. `STALE` saat ini hanya notifikasi admin, bukan boundary sebelum password didekripsi dan diteruskan.

**Confirmed:** fingerprint hanya mencakup path login dan nama field. Mode, method, final/action path, serta sebagian kontrak API dapat berubah tanpa membatalkan approval; scan yang tidak lagi menemukan kandidat juga tidak menandai profile stale.

Hasil discovery baru memakai serializer profile yang lengkap, sedangkan relation pada daftar/detail `PortalApp` tidak. **Confirmed** objek yang dibuka ulang UI tidak memiliki `requiresApproval`, sehingga kandidat pending/stale mendapat aksi “Terapkan profile” dan baru ditolak saat simpan.

**Confirmed:** state evidence transport/kredensial belum memiliki producer, dan operasi discovery/approval memakai read-then-write tanpa compare-and-set. Lifecycle tidak dapat menunjukkan hasil verifikasi nyata dan dapat kehilangan transisi saat operasi tumpang tindih.

Gunakan upsert/compare-and-set fingerprint dan lease atau retry lintas proses.
8. **P2 — The new security state machine has no regression coverage (confirmed; add before merge with the blockers)** — tidak ada test yang menutup redaction, stale launch blocking, fingerprint drift, no-candidate revalidation, UI serialization, atau race discovery/approval. Tambahkan test seam untuk transisi tersebut sebelum profile dipercaya sebagai credential-release control.

<summary>Details</summary>

### Redirect evidence crosses the non-secret storage boundary

**Confirmed:** `classifySsoMode()` membangun warning redirect dengan `finalUrl` mentah. `buildLoginProfileCandidate()` menyalin warning/signal ke kandidat, lalu `recordLoginProfileCandidate()` menulisnya ke `portal_login_profiles` dan `portal_login_profile_evidence`; serializer dan UI admin mengembalikannya lagi. Kolom URL memang melewati `locationFrom()`, tetapi text bebas ini tidak.

Dampaknya **likely** pada target dengan redirect ber-query, terutama alur SAML/WS-Fed/OIDC yang sudah didukung oleh batas URL login. Query dapat memuat state, relay state, assertion bertanda tangan, atau nilai bearer-like. `classifySsoMode()` juga menyimpan nama cookie pasangan antiforgery dalam signal; nilainya tidak disimpan, tetapi namanya tetap metadata respons yang tidak dibatasi. Persist hanya origin/path ternormalisasi dan bukti enum/boolean seperti `redirected`, `federated`, atau `hasPairedAntiforgeryCookie`.

### A stale profile remains advisory while FORM SSO releases passwords

**Confirmed:** discovery/revalidasi dapat memberi state `STALE`, tetapi `SsoLaunchPage` tidak memilih relation profile atau fingerprint binding. Halaman itu mendekripsi kredensial dan mengirim password ke `SSOAutoSubmit`, yang mem-post ke `loginUrl` tanpa memeriksa `approvalStatus`, `state`, `approvedFingerprint`, atau `loginProfileFingerprint`.

Risiko **confirmed** untuk FORM dan **likely** pada dispatcher credential-bearing lain. Sebelum dekripsi, guard bersama harus mensyaratkan profile approved, non-stale, dan `currentFingerprint === approvedFingerprint === PortalApp.loginProfileFingerprint`; failure path harus credentialless dan eksplisit.

### The drift fingerprint omits behavior that the profile claims to approve

**Confirmed:** `computeLoginFingerprint()` hanya meng-hash pathname, username/password field, dan nama extra field. `buildLoginProfileCandidate()` menyimpan `finalPath`, `formActionPath`, `httpMethod`, `recommendedMode`, dan kontrak API, tetapi `recordLoginProfileCandidate()` menentukan perubahan dan `STALE` dari hash yang lebih sempit. Mode dapat berubah FORM→POST/REROUTE, method/action dapat berubah, dan app terikat tetap memakai konfigurasi lama tanpa review.

`profileMatchesConfiguration()` hanya melindungi save berikutnya, bukan app yang sudah terikat, dan tidak membandingkan nama extra field. Bentuk satu snapshot versioned dari seluruh atribut routing non-secret—origin/path target, final/action path, method, mode, nama field terurut, dan kontrak ternormalisasi—lalu gunakan snapshot itu pada discovery, approval, binding, dan guard launch. Jangan masukkan query, nilai hidden field, cookie, atau kredensial.

### Successful scans with no candidate do not invalidate a prior approval

**Confirmed:** jika `detectWithLadder()` tidak menghasilkan form atau kontrak API, `recordLoginProfileCandidate()` mengembalikan `null`. `revalidateLoginProfileIfDue()` hanya mengubah `lastCheckedAt` dan `lastError`; `approvalStatus`, `approvedFingerprint`, serta `state` tetap aktif, dan health check tidak membuat audit stale.

Scan yang selesai tetapi tidak lagi melihat struktur login yang disetujui harus membuat profile `STALE` atau state ineligible setara. Error jaringan dapat tetap retryable, tetapi perlu dibedakan secara eksplisit dari observasi struktur yang hilang.

### The API gives the review component a different profile contract after reload

**Confirmed:** discovery/approval memakai `serializeLoginProfile()`, yang menghitung `requiresApproval`. Kedua `loginProfileSelect` pada route `PortalApp` mengembalikan relation mentah tanpa field itu. `openEditModal()` meneruskannya ke `LoginProfileReview`, sehingga `undefined` diperlakukan false dan component memilih `onApply` untuk profile pending atau stale.

Status label masih dapat berkata pending/stale, tetapi save kemudian ditolak `resolveApprovedProfileBinding()` dengan 409. Serialize relation sebelum response, atau hitung predicate dari status, fingerprint, dan state di client; jangan pertahankan dua kontrak `LoginProfileSummary` yang tampak sama tetapi berbeda perilaku.

### Verification labels have no producing flow

**Confirmed:** `recordLoginProfileVerification()` hanya dideklarasikan dalam modul baru. Verify-login hanya memperbarui `PortalApp.loginVerifiedAt`/`loginVerifyError`, dan health revalidation hanya menyimpan observasi discovery. Karena itu timestamp/state yang ditampilkan `LoginProfileReview` tidak merepresentasikan outcome verifikasi.

Integrasi harus memakai outcome terstruktur. Jalur JSON sengaja memperlakukan 401/403 sebagai transport hidup sekaligus kredensial ditolak, sehingga boolean `ok` tidak boleh langsung dipetakan ke `CREDENTIAL_ACCEPTED`. Catat outcome hanya pada fingerprint profile yang masih terikat.

### Profile updates are not serialized across discovery, revalidation, and approval

**Confirmed:** candidate recording membaca profile sebelum transaksi, dan approval membaca sebelum update tanpa kondisi. Discovery yang bersamaan dapat mengubah `currentFingerprint` di antaranya; approval lalu dapat menulis `approvedFingerprint` lama, menghapus `staleAt`, atau mengembalikan state usang. Resolver kemudian fail-closed pada save baru, tetapi UI/profile tetap menyesatkan.

`activeRevalidations` hanya mendeduplikasi proses Node yang sama. Pada worker/instance lain, revalidasi dan first-create masih dapat berpacu; salah satu admin akan melihat persistence warning bila unique `(origin, entryPath)` kalah. Gunakan conditional update berdasarkan fingerprint/version, retry unique conflict, dan lease database atau lock pendek bila health berjalan multi-proses.

### Regression coverage is absent at the new trust boundary

**Confirmed:** diff lokal tidak menambah test profile-focused, dan package scripts tidak menyediakan command test untuk state machine ini. TypeScript, lint, Prisma schema validation, dan diff whitespace lulus, tetapi tidak mengeksekusi discovery persistence, approval, revalidation, atau credential release.

Not tested: redaction query/cookie, mode/action/method drift tanpa perubahan field, reachable no-candidate, stale blocking sebelum dekripsi, serialisasi setelah reload, outcome verification, dan race discovery/approval.
