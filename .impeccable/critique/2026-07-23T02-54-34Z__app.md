## Anti-Patterns Verdict
Looks AI-generated — from excessive consistency in the wrong places. Same 11px / letterSpacing 0.2em / #dc2626 uppercase eyebrow on EVERY header (33+: "OVERVIEW","AKTIVITAS PERUSAHAAN","BUAT BARU","EDIT","PORTAL SSO","RIWAYAT REVISI","AUDIT TRAIL"). Hero-metric template (big number + uppercase label + colored icon + side-stripe) repeated verbatim across admin/page.tsx:60-65,129, AnalyticsDashboard.tsx:422, SiteHealthCard.tsx:216, global-analytics. Side-stripe borderLeft:4px (detector caught admin/page.tsx:129, AnalyticsDashboard.tsx:422). Dead giveaway: ~50 alert() + ~15 confirm() across admin/portal coexisting with a real ToastContext.

Deterministic scan (detect.mjs, exit 2): 7 warnings — 4 overused-font (globals.css Inter/Montserrat), 2 side-tab, 1 layout-transition (AdminMainContent.tsx:29 animates margin-left). 0 false positives. Browser visualization unavailable (no browser tool exposed; Playwright not installed) — CLI + source inspection only.

## Overall Impression
Functional product with real thinking (bulk actions, autosave, excellent portal error states) drowning in templated decoration and a design system its own authors don't follow. Biggest opportunity: make tokens + primitives binding (one red, one font load, one toast, one confirm, one focus ring), then strip reflexive decoration.

## What's Working
1. Portal credential error states (CorruptCredential.tsx, NoCredential.tsx, AccessDenied.tsx) — plain Bahasa, one icon, one CTA, restrained color. The design bar for the rest of the app.
2. BulkActionBar.tsx:60-148 + AnnouncementForm.tsx:76 autosave — real power-user task fluency.
3. globals.css ships :focus-visible (224-227), .sr-only (230-240), skip link (243-256) — a11y intent present (later overridden by inline outline:none).

## Priority Issues

Fix: add reduced-motion media query; remove inline outline:none; use <button>; raise #525252 -> #a1a1aa. Cmd: $impeccable audit then $impeccable harden

**[P1] No single feedback/confirm primitive — ~50 alert() + ~15 confirm() vs real ToastContext + custom delete modal (AnnouncementsList.tsx:406).** Fix: make useToast() + one ConfirmDialog the only legal primitives; replace all alert()/confirm(); ESLint no-restricted-globals. Cmd: $impeccable clarify then $impeccable polish

**[P1] Tokens have no authority — 3 reds** (tailwind #ED1C24 config:14, css #dc2626 globals:11, theme #FF4D54 SiteThemeProvider.tsx:35); #dc2626 inline 175x, #ef4444 51x; **double font load** (@import globals:1 + next/font layout:7-18); pervasive inline style={}. Fix: one red token everywhere; delete @import (keep next/font); replace inline styles with utilities. Cmd: $impeccable colorize then $impeccable document

**[P1] AI-slop decoration uniform —** eyebrow on every section (33+); hero-metric grids repeated; side-stripes; ALL-CAPS nav; decorative gradients (admin-login:51) + glass nav (site search:81, article:114). **[P1] IA + emotional journey mismatch —** 18 flat sidebar items (AdminSidebar.tsx:77-98) + live clock re-rendering/sec (:64-70); login shows raw "CredentialsSignin" (admin-login:28-29) with no recovery, while portal recovery states are the best screens. ## Questions to Consider
1. ToastContext + custom delete modal exist but ~half the app uses alert()/confirm(). What would make toast + one ConfirmDialog the only legal primitives?
2. 18 equal-weight sidebar items for a SuperAdmin who does 3-4 things/session — why not group into collapsible sections?
3. Portal recovery states are the best screens, yet login failure shows raw "CredentialsSignin". Why spend emotional-design budget on recovery, not the moment of failure?
